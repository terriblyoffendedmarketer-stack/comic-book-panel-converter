# Learnings

what broke | why | what fixed it
---|---|---
EPUB extraction missing | extract.py only handled CBZ/CBR/CB7 | Added extract_epub (unzip images from OEBPS/) and extract_pdf (PyMuPDF at 200 DPI)
Universal conversion approach fails for mixed comics | Philosophy graphic novels have wildly different layouts (3-row grid, 2x2 grid, 2 horizontal panels, landscape full-page, text-heavy) | Per-comic strategy: analyze visual style and assign each to best device/method
Overlapping thirds bad for clean panel layouts | Thirds arbitrarily slice the page at 1/3 intervals regardless of gutter positions; for comics with clean panel boundaries, this cuts through panels | Panel-per-page (Kumiko detect → individual panel crop → XTC) preserves each panel's integrity
Dithering choice matters per art style | Atkinson is too harsh for painterly/gradient art; Floyd-Steinberg is too soft for bold B&W | Atkinson for bold B&W line art (99 Ways, Labyrinth), Floyd-Steinberg for painterly (Verissimus, Aristotle)
Landscape comics (Here by McGuire) can't split | Full-page compositions where the entire page IS the artistic unit — splitting destroys the concept | Kindle-only (full page, user rotates device sideways)
rarfile glob escaping | Python raw strings with apostrophes in filenames break rarfile.RarFile() | Use glob.glob() to find files instead of constructing paths with special characters
Corrupt CBR pages crash rarfile | rarfile.BadRarFile on CRC mismatch kills extraction entirely (Logicomix page 283/332) | Catch BadRarFile per-file and skip corrupt pages; also use unar directly as fallback (more CRC-tolerant)
KCC fails on some CBR filenames | KCC's internal extraction chokes on special chars in filenames (parentheses, dots) | Always extract to directory first via our extract.py, then pass directory to KCC
Parallel temp dir conflict | Two conversion processes sharing `_temp` directory → Kindle cleanup deletes XTe Ink's working files | Use separate temp dirs per device: `_temp_kindle`, `_temp_xteink`
KCC + Kumiko fail badly on philosophy graphic novels | KCC drops text-only pages entirely, speech bubble content disappears, page splitting is nonsensical. Kumiko panel detection is designed for manga gutters, not mixed text/art layouts. These tools were built for manga, not text-heavy Western graphic novels with irregular layouts. | SOLVED — Row-splitting pipeline: detect horizontal gutters between panel rows (10th percentile brightness), split into 2-3 rows, each row fills landscape viewport. Text goes from ~5pt to ~13pt. No KCC or Kumiko needed.
Row average brightness detects false gutters | Using row average brightness > 220 found 17-28 "gutters" per page because text line spacing registers as gaps | Use 10th percentile brightness across center 80% of width — text lines have dark character pixels that pull the percentile down, but true gutters have no dark pixels even at P10. Merge candidates within 40px.
EPUB graphic novel text layers are HTML overlays | Publisher EPUBs store dialog as positioned `<div>` elements over background JPEGs with empty speech bubbles — extracting just images loses all text | Render EPUB→PDF via Calibre `ebook-convert` with `--custom-size WxH --unit point --pdf-page-margin-* 0` matching EPUB viewport to composite text onto images
Calibre default page size adds whitespace | EPUB→PDF with default letter-size (612x792pt) creates massive margins around comic content sized for smaller EPUB viewport | Match `--custom-size` to EPUB viewport dimensions (e.g., 770x880 for Labyrinth, 822x1125 for Aristotle)
XTCH beats XTC for text-heavy comics | 1-bit XTC dithering adds noise that obscures small text in speech bubbles | XTCH 4-level grayscale quantization (no dithering) preserves text clarity — 4 levels enough for comic art shading
